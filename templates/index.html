Architecture

How It Works

The end-to-end Machine Learning processing flow from user input to classification.

1

Raw Input

User inputs message text via web application interface.

2

Preprocessing

Lowercases, normalizes URLs, currency ($/£/€/₹), emails, exclamations, and whitespace.

3

TF-IDF

Converts cleaned text into numerical n-gram sublinear term frequency vectors.

4

Naive Bayes

Calculates posterior class probabilities with tuned Laplace smoothing (α=0.1).

5

Output & DB

Returns SPAM/HAM label + confidence and stores in SQLite.

Overview

About the Project

Understanding spam detection, machine learning principles, and lab objectives.

Problem Statement: Spam emails and fraudulent messages represent a major cybersecurity and productivity issue, exposing users to financial scams, credential theft, and malware. Rule-based filters frequently fail against evolving vocabulary and deceptive spam tactics.

Why Machine Learning? Machine Learning algorithms learn subtle statistical word frequency distributions and co-occurrences across thousands of messages. By converting raw text into Term Frequency-Inverse Document Frequency (TF-IDF) feature vectors with normalized currency symbols and tokens, the system accurately predicts spam intent with {{ metrics.get('accuracy', 98.26) }}% accuracy, {{ metrics.get('precision', 97.48) }}% precision, and {{ metrics.get('recall', 88.55) }}% recall.

Academic Lab Mapping: This project satisfies standard university Machine Learning Lab curriculum requirements: Data Preprocessing, TF-IDF Vectorization, Stratified Splitting, Naive Bayes Classification & Algorithm Comparison, Confusion Matrix calculation, Model Serialization (Joblib), SQLite CRUD integration, Light/Dark theme personalization, and Full-Stack Web Deployment.
